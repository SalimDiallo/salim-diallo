# Guide de Workflow Git : Du Chaos à la Clarté

Git est puissant, mais les équipes ont souvent du mal parce qu'elles ne s'accordent pas sur quelques bases. Un workflow simple garde l'historique lisible, les revues ciblées et les releases moins stressantes.

Voici un guide léger que vous pouvez adopter en une journée et améliorer par la suite.

## Un workflow d'équipe simple

- Créez une branche depuis `main` pour chaque modification.
- Gardez les branches petites et de courte durée.
- Ouvrez une pull request tôt et demandez une revue.
- Fusionnez vers `main` une fois les tests passés.

## Conseils pour les messages de commit

- Commencez par un verbe clair ("ajouter", "corriger", "supprimer", "refactoriser").
- Gardez la première ligne courte et spécifique.
- Préférez plusieurs petits commits à un seul "WIP" géant.

## Checklist de PR

1. Expliquez ce qui a changé et pourquoi.
2. Liez l'issue ou décrivez l'impact utilisateur.
3. Ajoutez des tests (ou expliquez pourquoi non).
4. Gardez le diff assez petit pour être revu rapidement.

## Conclusion

L'objectif n'est pas un "Git parfait" — c'est moins de surprises et une collaboration plus rapide. Commencez simple, documentez les règles et améliorez-les au fur et à mesure que votre équipe grandit.
